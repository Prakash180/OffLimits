Module 16 · Build Your Own Local Identity Provider

🧠 Mental Model — Behind the Scenes

How an identity provider issues and verifies trust

Picture a passport office (the identity provider) and a border agent (your API). You don't expect the border agent to phone the passport office and re-check your fingerprints every time you cross. Instead, the passport office signs your passport with a tamper-evident seal, and publishes a catalogue of its official seals. Any border agent who trusts that catalogue can verify your passport on the spot — offline, in milliseconds.

A JWT-issuing IdP works exactly like that.

Issuing (the passport office)

When a user logs in, the IdP gathers the facts it's willing to vouch for — who the user is (sub, email, name), what they may do (scope, roles), and for how long (exp) — and packs them into a JSON payload. It then signs that payload with the private half of an RSA keypair using RS256. The signature is a number that only the holder of the private key could have produced, yet anyone with the public key can check. Crucially, the IdP stamps the token's header with a kid — the id of the exact key it signed with — so the verifier knows which seal to look up.

The private key never leaves the IdP. What the IdP does share, freely and publicly, is the matching public key, served as a JWKS (JSON Web Key Set) at a stable URL.

flowchart LR U[User logs in] --> S[IdP builds claims<br/>iss·aud·sub·exp·scope] S --> K[Sign RS256 with PRIVATE key<br/>add kid to header] K --> T[Token handed to client] T --> R[Resource server] R --> J[Fetch JWKS by kid<br/>PUBLIC key only] J --> V[Verify signature·iss·aud·exp] V --> Y[Trust the claims]

Verifying (the border agent)

The resource server receives Authorization: Bearer <token>. It reads the unverified header just to learn the kid, fetches the IdP's JWKS, and picks the public key whose kid matches. Then it runs jwt.decode(...), which re-computes the signature and rejects anything tampered, expired, issued by the wrong party (iss), or meant for someone else (aud). No shared password, no callback to the IdP — just public-key math.

Why the catalogue has more than one seal

Passport offices retire old seals and mint new ones. If they swapped instantly, every passport signed yesterday would suddenly look forged. So they keep the old and new seal in the public catalogue at once and route by seal id. That is precisely why a JWKS publishes a set of keys and tokens carry a kid: rotation becomes invisible to everyone holding a still-valid token, while retired keys quietly age out and their tokens stop validating.

That single idea — sign privately, verify publicly, route by kid — is the entire trust backbone behind Microsoft Entra ID, Google, Auth0, and the local provider you just built.

🏛️ Module 16 · Build Your Own Local Identity Provider

"You've spent 15 modules verifying other people's tokens. Now you become the one who issues them."

This module ships a fully local, offline OAuth2 + OpenID Connect (OIDC) identity provider built on FastAPI + PyJWT + cryptography. It mirrors the exact shape of Microsoft Entra ID / Google / Auth0 — discovery document, JWKS, authorize, token, userinfo — so you can run the complete authorization-code flow, validate tokens against a JWKS, exchange refresh tokens, and watch key rotation happen live, all without a single network call and without an Azure subscription.

Every numbered script drives the provider in-process with fastapi.testclient.TestClient, so it runs to completion and exits 0. A real uvicorn entrypoint is provided for interactive use.

🧭 OAuth2 authorization-code + OIDC, in one paragraph

In the authorization-code flow, your app never sees the user's password. It sends the browser to the IdP's /authorize endpoint; the user authenticates; the IdP hands back a single-use code at your redirect URI. Your backend then POSTs that code (plus its client_secret) to /token and receives an access_token (a key to an API), an id_token (OIDC proof of who logged in), and a refresh_token (to get fresh access tokens later). The API validates the access token by fetching the IdP's public keys from its JWKS and checking the RS256 signature, iss, aud, and exp. OIDC is the thin identity layer on top of OAuth2 that adds the id_token and the discovery/JWKS conventions.

🎯 Key takeaways

  • An IdP signs with a private key and publishes the public key as a JWKS; resource servers verify with that public key — they never hold a secret.
  • The kid header is the routing glue: it tells the verifier which JWKS key to use, which is what makes zero-downtime key rotation possible.
  • access_token (aud = API) and id_token (aud = client_id) answer two different questions: what may I call? vs who is this user?
  • The nonce binds an id_token to the exact login request that asked for it.
  • Refresh tokens trade a long-lived credential for short-lived access tokens so a leaked access token expires fast.
  • Swapping localhost:9000 for a real provider's discovery URL is the only change needed to point this code at Azure/Google.

02 JWKS Endpoint02_jwks_endpoint.py ▾

A provider signs tokens with a PRIVATE key and publishes the matching PUBLIC key as a JWK (JSON Web Key) in a JWKS (JSON Web Key Set) at jwks_uri.

Each JWK carries:

  • kty — key type (RSA here).
  • n / e — the RSA public modulus and exponent (the actual key material).
  • kid — key id; the JWT header's kid points at exactly one of these.
  • use / alg — intended use (sig) and algorithm (RS256).

Our IdP publishes TWO keys at once (current + next) so that validation keeps working across a key rotation (see script 08).

"""
02 · The JWKS endpoint — how clients learn the provider's public keys
=====================================================================

A provider signs tokens with a PRIVATE key and publishes the matching PUBLIC
key as a JWK (JSON Web Key) in a JWKS (JSON Web Key Set) at ``jwks_uri``.

Each JWK carries:

* ``kty`` — key type (``RSA`` here).
* ``n`` / ``e`` — the RSA public modulus and exponent (the actual key material).
* ``kid`` — key id; the JWT header's ``kid`` points at exactly one of these.
* ``use`` / ``alg`` — intended use (``sig``) and algorithm (``RS256``).

Our IdP publishes TWO keys at once (``current`` + ``next``) so that validation
keeps working across a key rotation (see script 08).

Run:
    uv run python pyjwt-course/16-local-identity-provider/02_jwks_endpoint.py
"""

import json

from idp.client import LocalIdPClient


def main() -> None:
    client = LocalIdPClient()
    jwks = client.jwks()

    print("=" * 72)
    print("JWKS  (GET /jwks.json)  — public verification keys only")
    print("=" * 72)

    for i, jwk in enumerate(jwks["keys"], start=1):
        preview = dict(jwk)
        # The modulus `n` is huge; truncate it for readable output.
        preview["n"] = preview["n"][:32] + "...(truncated)"
        print(f"\nKey #{i}:")
        print(json.dumps(preview, indent=2))

    print("\n" + "=" * 72)
    print("FIELD-BY-FIELD")
    print("=" * 72)
    print("• kty=RSA   the key is an RSA key")
    print("• n, e      the public modulus + exponent (the verifiable key material)")
    print("• kid       the id a token's header names so clients pick THIS key")
    print("• use=sig   this key is for signature verification")
    print("• alg=RS256 RSASSA-PKCS1-v1_5 using SHA-256")

    kids = [k["kid"] for k in jwks["keys"]]
    print(f"\nPublished kids: {kids}")
    print("Two keys are advertised so a freshly-rotated key is already trusted")
    print("by clients that cached the JWKS a moment ago.")

    assert len(jwks["keys"]) == 2
    assert all(k["kty"] == "RSA" and k["use"] == "sig" for k in jwks["keys"])
    print("\nOK ✔  JWKS contains two well-formed RSA signing keys.")


if __name__ == "__main__":
    main()

"""
03 · The authorization-code flow, end to end (locally)
======================================================

This is the heart of OAuth2 + OIDC. The confidential auth-code flow:

    1. Client redirects the browser to  GET /authorize?...   (user logs in)
    2. Provider redirects back with      ?code=...           (a one-time code)
    3. Client POSTs the code to          POST /token         (+ client_secret)
    4. Provider returns                  access_token, id_token, refresh_token

We run all four steps against the LOCAL IdP in-process and decode the tokens so
you can see exactly what comes out. (Token VALIDATION via JWKS is script 04.)

Run:
    uv run python pyjwt-course/16-local-identity-provider/03_authorization_code_flow.py
"""

import json

import jwt
from idp.client import LocalIdPClient


def show(label: str, token: str) -> None:
    """Pretty-print a JWT's header + payload WITHOUT verifying (inspection)."""
    header = jwt.get_unverified_header(token)
    payload = jwt.decode(token, options={"verify_signature": False})
    print(f"\n{label}")
    print(f"  header : {json.dumps(header)}")
    print(f"  payload: {json.dumps(payload, indent=2)}")


def main() -> None:
    client = LocalIdPClient()

    print("=" * 72)
    print("STEP 1+2 · GET /authorize  ->  one-time authorization code")
    print("=" * 72)
    code = client.authorize(
        scope="openid profile email api.read",
        nonce="n-onceabc123",
        state="opaque-state-xyz",
    )
    print(f"Received authorization code: {code[:16]}... (single-use, short-lived)")

    print("\n" + "=" * 72)
    print("STEP 3+4 · POST /token  ->  exchange code for tokens")
    print("=" * 72)
    tokens = client.exchange(code)
    print("Token response fields:")
    for k, v in tokens.items():
        shown = v if k in {"token_type", "expires_in", "scope"} else f"{str(v)[:24]}..."
        print(f"  {k}: {shown}")

    show("ACCESS TOKEN (for the resource API — note aud + scope)", tokens["access_token"])
    show("ID TOKEN (OIDC identity for the client — note nonce/email/name)", tokens["id_token"])

    print("\n" + "=" * 72)
    print("WHAT JUST HAPPENED")
    print("=" * 72)
    print("• The code was exchanged exactly once; replaying it would 400.")
    print("• access_token.aud = the API; id_token.aud = the client_id.")

from idp.server import AUDIENCE, ISSUER


def signing_key_from_jwks(token: str, jwks: dict):

        token,
        key,
        algorithms=["RS256"],
        audience=AUDIENCE,
        issuer=ISSUER,

"""
06 · The refresh-token grant — fresh access tokens without re-login
===================================================================

Access tokens are deliberately short-lived (15 minutes here). Rather than make
the user log in again every 15 minutes, the client keeps the long-lived
``refresh_token`` and exchanges it at ``/token`` for a brand-new access token:

    POST /token
        grant_type=refresh_token
        refresh_token=<the opaque token>
        client_id / client_secret

This script logs in once, then refreshes, and compares the OLD vs NEW token
expiry to prove the access token's lifetime was extended.

Run:
    uv run python pyjwt-course/16-local-identity-provider/06_refresh_token_flow.py
"""

from datetime import UTC, datetime

import jwt


def exp_of(token: str) -> datetime:
    """Read the `exp` claim from a JWT without verifying (inspection only)."""
    payload = jwt.decode(token, options={"verify_signature": False})
    return datetime.fromtimestamp(payload["exp"], tz=UTC)


def main() -> None:
    # Imported here so the module import line is part of the visible lesson.
    from idp.client import LocalIdPClient

    client = LocalIdPClient()

    print("=" * 72)
    print("STEP 1 · initial login (authorization_code grant)")
    print("=" * 72)
    tokens = client.login(scope="openid api.read")
    old_access = tokens["access_token"]
    refresh_token = tokens["refresh_token"]
    print(f"access_token  exp: {exp_of(old_access).isoformat()}")
    print(f"refresh_token    : {refresh_token[:16]}... (kept by the client)")

    print("\n" + "=" * 72)
    print("STEP 2 · refresh_token grant  ->  a fresh access token")
    print("=" * 72)
    refreshed = client.refresh(refresh_token)
    new_access = refreshed["access_token"]
    print(f"new access_token exp: {exp_of(new_access).isoformat()}")

    print("\n" + "=" * 72)
    print("OLD vs NEW")
    print("=" * 72)
    print(f"old exp: {exp_of(old_access).isoformat()}")
    print(f"new exp: {exp_of(new_access).isoformat()}")
    print(f"new token is a distinct credential (different jti): {new_access != old_access}")
    print(f"new expiry is later or equal: {exp_of(new_access) >= exp_of(old_access)}")
    print("(Issued back-to-back here, so exp can match to the second; in real use")
    print(" the refresh happens minutes later and the new exp strictly advances.)")

    assert new_access != old_access
    assert exp_of(new_access) >= exp_of(old_access)
    assert "refresh_token" in refreshed  # the grant also rotates the refresh token
    print("\nOK ✔  refresh grant issued a new, longer-lived access token.")

"""
07 · The OIDC id_token and the nonce round-trip
===============================================

OAuth2 gives you an **access_token** (a key to an API). OpenID Connect adds an
**id_token**: proof of *who logged in*, issued FOR THE CLIENT.

Key differences:

    access_token   aud = the resource API   "what may I call?"

then checks ``id_token.nonce == the nonce I sent`` — defeating replay/injection
of a stolen id_token.

This script logs in with a nonce, validates the id_token's iss/aud/exp, and
verifies the nonce round-trips.

Run:
    uv run python pyjwt-course/16-local-identity-provider/07_id_token_and_nonce.py
"""

import jwt
from idp.client import CLIENT_ID, LocalIdPClient
from idp.server import ISSUER


def signing_key_from_jwks(token: str, jwks: dict):
    """Select the public key from the JWKS whose kid matches the token."""
    kid = jwt.get_unverified_header(token)["kid"]
    keyset = jwt.PyJWKSet.from_dict(jwks)
    for key in keyset.keys:
        if key.key_id == kid:
            return key.key
    raise jwt.PyJWKClientError(f"no key for kid={kid!r}")


def validate_id_token(id_token: str, jwks: dict, expected_nonce: str) -> dict:
    """Validate an id_token: signature, iss, aud(=client_id), exp, and nonce."""
    key = signing_key_from_jwks(id_token, jwks)
    claims = jwt.decode(
        id_token,
        key,
        algorithms=["RS256"],
        audience=CLIENT_ID,  # id_token audience MUST be our client_id
        issuer=ISSUER,
        options={"require": ["exp", "iss", "aud", "sub"]},
    )
    # nonce is application-level: PyJWT won't check it for us.
    if claims.get("nonce") != expected_nonce:
        raise jwt.InvalidTokenError("nonce mismatch — possible replay")
    return claims

3. shows the token from the still-published key keeps validating;

"""
08 · Live key rotation — why providers publish more than one key
================================================================

Providers periodically retire their signing key and start signing with a new
one. If they swapped instantly, every token signed by the old key would break
the moment clients refreshed the JWKS. The fix: publish a SET of keys (current +
next) and route by ``kid``. A token verifies as long as its ``kid`` is still in
the JWKS — regardless of which published key signed it.

This script:

    1. publishes two keys and signs a token with EACH — both validate;
    2. rotates (current -> retired, next -> current, new next minted);
    3. shows the token from the still-published key keeps validating;
    4. shows the token from the RETIRED key now fails (its kid left the JWKS).

It mutates the IdP's live ``KeyManager`` (``idp.server.keys``) directly.

Run:
    uv run python pyjwt-course/16-local-identity-provider/08_key_rotation_live.py
"""

from datetime import UTC, datetime, timedelta

import jwt
from idp.server import AUDIENCE, ISSUER, keys


def sign_access_token(signer, sub: str = "user-alice-0001") -> str:
    """Sign a minimal RS256 access token with a SPECIFIC signing key."""
    now = datetime.now(UTC)
    return jwt.encode(
        {
            "iss": ISSUER,
            "aud": AUDIENCE,
            "sub": sub,
            "scope": "api.read",
            "iat": now,
            "exp": now + timedelta(minutes=15),
        },
        signer.private_key,
        algorithm="RS256",
        headers={"kid": signer.kid},
    )


def validate(token: str, jwks: dict) -> dict:
    """Validate a token by selecting its key from the CURRENT JWKS via kid."""
    kid = jwt.get_unverified_header(token)["kid"]
    keyset = jwt.PyJWKSet.from_dict(jwks)
    for key in keyset.keys:
        if key.key_id == kid:
            return jwt.decode(
                token, key.key, algorithms=["RS256"],
                audience=AUDIENCE, issuer=ISSUER,
            )
    raise jwt.PyJWKClientError(f"no published key for kid={kid!r}")


def main() -> None:
    print("=" * 72)
    print("BEFORE ROTATION · two keys published")
    print("=" * 72)
    print(f"published kids: {[k['kid'] for k in keys.jwks()['keys']]}")

    current_key = keys.current
    next_key = keys.next
    token_from_current = sign_access_token(current_key)
    token_from_next = sign_access_token(next_key)

    jwks_before = keys.jwks()
    validate(token_from_current, jwks_before)
    validate(token_from_next, jwks_before)
    print(f"token signed by current ({current_key.kid}) -> VALID ✔")
    print(f"token signed by next    ({next_key.kid}) -> VALID ✔")
    print("Both published keys validate — that's why a set is published.")

    print("\n" + "=" * 72)
    print("ROTATE · current retires, next becomes current, a new next is minted")
    print("=" * 72)
    retired = keys.rotate()
    jwks_after = keys.jwks()
    print(f"retired kid   : {retired.kid}")
    print(f"published kids: {[k['kid'] for k in jwks_after['keys']]}")

    print("\n" + "=" * 72)
    print("AFTER ROTATION · who still validates?")
    print("=" * 72)
    # token_from_next was signed by the key that is now `current` -> still published.
    validate(token_from_next, jwks_after)
    print(f"token signed by {next_key.kid} (now current) -> STILL VALID ✔")

    # token_from_current was signed by the now-retired key -> kid gone from JWKS.
    try:
        validate(token_from_current, jwks_after)
        print("UNEXPECTED: retired-key token still accepted!")
        raise SystemExit(1)
    except jwt.PyJWKClientError as exc:
        print(f"token signed by {retired.kid} (retired) -> REJECTED: {exc}")

    print("\nOK ✔  rotation kept valid tokens working and aged the old key out.")
