Module 12 · Validation, Errors & Leeway

🧠 Mental Model — Behind the Scenes

jwt.decode looks like a single function call, but internally it is a pipeline of independent checks run in a specific order: is the string structurally three base64url segments? Does the signature verify against the key and pinned algorithm? Is exp in the past? Is nbf in the future? Does aud include us? Is iss trusted? Are all required claims present? Each gate that fails raises a specific, typed exception — and crucially, those exceptions form an inheritance tree rooted at PyJWTError. That tree is the secret to writing auth code that is both robust and precise.

The hierarchy matters because of how Python's except matching works: it catches by class and subclass. InvalidSignatureError is a DecodeError is an InvalidTokenError is a PyJWTError. So except InvalidTokenError is the practical "reject this token" catch-all, while except ExpiredSignatureError lets you respond narrowly — say, by offering a token refresh instead of a hard 401. The rule that falls out of this: order your except blocks most-specific first, otherwise a broad catch placed too early silently swallows the precise cases you wanted to distinguish.

The other half of this module is leeway — a deliberate tolerance for clock skew. Two servers never agree on the time to the millisecond; a token minted on a machine running three seconds fast can look "not yet valid" (nbf in the future) or "already expired" on a machine running slightly behind. leeway= (in seconds) widens the acceptance window on both the exp and nbf comparisons, so a token that is just barely outside the boundary still passes. The implementation is simply: compare now against exp + leeway and nbf - leeway instead of the raw values. Keep it to a few seconds — leeway=3600 would mean expired tokens live an extra hour, which is a real security regression dressed up as forgiveness.

🔍 A concrete analogy

Think of airport boarding. A malformed boarding pass (unreadable barcode) is turned away at the scanner — that's a DecodeError. A forged pass with a bad signature is a InvalidSignatureError. A pass for yesterday's flight is ExpiredSignatureError; one for tomorrow's flight is ImmatureSignatureError; the right pass but for the wrong gate is InvalidAudienceError. Leeway is the gate agent letting you board 30 seconds after the official cutoff because their watch and yours disagree — a small, bounded grace, never an open door.

⚙️ What actually happens when you run the code

  1. jwt.decode first splits and base64url-decodes the token; a structural failure raises DecodeError.
  2. It recomputes/verifies the signature with your key and pinned algorithms; a mismatch raises InvalidSignatureError (a subclass of DecodeError).
  3. It checks time claims: exp against now (+ leeway) → ExpiredSignatureError; nbf against now (− leeway) → ImmatureSignatureError.
  4. It checks aud/iss if you passed audience=/issuer= → InvalidAudienceError / InvalidIssuerError.
  5. It enforces options={"require": [...]} → MissingRequiredClaimError if any are absent.
  6. The first failing gate raises; your except ladder catches it by its concrete type and maps it to a (ok, reason, http_status) triple.

👀 What to notice when you run the examples

  • 01_exception_hierarchy.py prints the actual class tree (via MRO) — you can see that InvalidSignatureError descends from DecodeError.
  • 02–06 each trigger exactly one error type on purpose, so you learn the cause→exception mapping by demonstration.
  • 07_leeway.py shows the same just-expired token being rejected without leeway and accepted with leeway=10.
  • 08_robust_validator.py never lets an exception escape — every path returns a friendly reason and an HTTP status, the production-grade shape.

⚠️ Common misconceptions

  • "Catch except Exception to be safe." That masks bugs and loses the precise reason; catch PyJWTError/InvalidTokenError instead.
  • "Order of except blocks doesn't matter." It absolutely does — broad-before-specific swallows the specific cases.
  • "Leeway is harmless slack." Large leeway extends the life of expired tokens; keep it to seconds.
  • "A token with no exp is fine." It never expires — use options={"require": ["exp"]} for anything sensitive.

🚦 Module 12 · Validation, Errors & Leeway

A token either verifies or it doesn't — but why it failed is the difference between a helpful 401 and a baffled user. This module maps PyJWT's exception hierarchy, triggers each failure on purpose, and builds a production-grade validator that never crashes.

🧠 The big idea

jwt.decode does a lot of checking: structure, signature, exp, nbf, aud, iss, required claims. Each distinct failure raises a specific exception, and those exceptions form an inheritance tree rooted at PyJWTError. Master the tree and you can:

  • Catch broadly — except InvalidTokenError to reject any bad token.
  • Catch narrowly — except ExpiredSignatureError to offer a refresh.
  • Tolerate clock skew — leeway= for tokens that are just expired/early.

🌳 The exception hierarchy

flowchart TD A[PyJWTError] --> B[InvalidTokenError] B --> C[DecodeError] C --> D[InvalidSignatureError] B --> E[ExpiredSignatureError] B --> F[ImmatureSignatureError] B --> G[InvalidAudienceError] B --> H[InvalidIssuerError] B --> I[InvalidIssuedAtError] B --> J[MissingRequiredClaimError] B --> K[InvalidAlgorithmError] B --> L[InvalidKeyError]

Order your except blocks most-specific first. Because InvalidSignatureError is a DecodeError is an InvalidTokenError, a broad catch placed too early will swallow the specific cases.

✅ Key takeaways

  • Every validation failure is a typed exception under PyJWTError.
  • InvalidTokenError is the practical catch-all for "reject this token".
  • Order except blocks specific → general, or specifics get swallowed.
  • leeway= forgives small clock skew on exp/nbf — keep it to seconds.
  • A good validator converts exceptions into (ok, reason, status) and never lets one escape to the caller.

⚠️ Pitfalls

  • Bare except Exception. You'll mask bugs and lose the precise reason. Catch PyJWTError/InvalidTokenError instead.
  • Leaking internals. Don't return raw exception text to end users for auth failures; map to friendly messages (as script 08 does).
  • Huge leeway. leeway=3600 means expired tokens live an extra hour — a real security regression.
  • Forgetting algorithms=[...]. Omitting it raises DecodeError; never work around that by trusting the token's own alg.
  • Not requiring exp. A token with no expiry never expires. Use options={"require": ["exp"]} for anything sensitive.

01 · The PyJWT exception hierarchy.

When validation fails, PyJWT raises a specific exception — and those exceptions form a tidy inheritance tree. Knowing the tree lets you catch broadly (PyJWTError for "anything JWT went wrong") or narrowly (ExpiredSignatureError for "just this case").

The hierarchy (rooted at PyJWTError):

PyJWTError
└── InvalidTokenError
    ├── DecodeError
    │   └── InvalidSignatureError
    ├── ExpiredSignatureError
    ├── InvalidAudienceError
    ├── InvalidIssuerError
    ├── InvalidIssuedAtError
    ├── ImmatureSignatureError        (nbf in the future)
    ├── InvalidKeyError
    ├── InvalidAlgorithmError
    └── MissingRequiredClaimError

Because almost everything subclasses InvalidTokenError, a single except InvalidTokenError is a safe catch-all for "reject this token", while except PyJWTError also covers encoding-side problems.

This script uses inspect to print each class's Method Resolution Order (MRO), which is its ancestry chain.

"""01 · The PyJWT exception hierarchy.

When validation fails, PyJWT raises a *specific* exception — and those exceptions
form a tidy inheritance tree. Knowing the tree lets you catch broadly
(``PyJWTError`` for "anything JWT went wrong") or narrowly
(``ExpiredSignatureError`` for "just this case").

The hierarchy (rooted at ``PyJWTError``):

    PyJWTError
    └── InvalidTokenError
        ├── DecodeError
        │   └── InvalidSignatureError
        ├── ExpiredSignatureError
        ├── InvalidAudienceError
        ├── InvalidIssuerError
        ├── InvalidIssuedAtError
        ├── ImmatureSignatureError        (nbf in the future)
        ├── InvalidKeyError
        ├── InvalidAlgorithmError
        └── MissingRequiredClaimError

Because almost everything subclasses ``InvalidTokenError``, a single
``except InvalidTokenError`` is a safe catch-all for "reject this token", while
``except PyJWTError`` also covers encoding-side problems.

This script uses ``inspect`` to print each class's Method Resolution Order (MRO),
which *is* its ancestry chain.

Run:
    /home/astro/catalyst/jwt-test/.venv/bin/python \
        pyjwt-course/12-validation-errors-and-leeway/01_exception_hierarchy.py
"""

import inspect

import jwt.exceptions as exc

# The classes we want to map, in a sensible teaching order.
CLASSES = [
    exc.PyJWTError,
    exc.InvalidTokenError,
    exc.DecodeError,
    exc.InvalidSignatureError,
    exc.ExpiredSignatureError,
    exc.InvalidAudienceError,
    exc.InvalidIssuerError,
    exc.ImmatureSignatureError,
    exc.MissingRequiredClaimError,
    exc.InvalidAlgorithmError,
    exc.InvalidKeyError,
]


def main() -> None:
    print("PyJWT exception ancestry (each line = class -> its base classes):")
    print()
    for cls in CLASSES:
        # MRO without 'object' and the class itself = its real ancestors.
        ancestors = [c.__name__ for c in inspect.getmro(cls) if c not in (cls, object)]
        chain = " -> ".join(ancestors) if ancestors else "(root)"
        print(f"  {cls.__name__:<25} : {chain}")
    print()

    # Demonstrate the practical payoff: broad vs. narrow catching.
    print("Subclass checks (why catch-alls work):")
    print(f"  ExpiredSignatureError is an InvalidTokenError? "
          f"{issubclass(exc.ExpiredSignatureError, exc.InvalidTokenError)}")
    print(f"  InvalidSignatureError is a DecodeError?        "
          f"{issubclass(exc.InvalidSignatureError, exc.DecodeError)}")
    print(f"  Every error is a PyJWTError?                   "
          f"{all(issubclass(c, exc.PyJWTError) for c in CLASSES)}")
    print()
    print("✅ Catch InvalidTokenError to reject any bad token; subclasses for detail.")


if __name__ == "__main__":
    main()

The exp (expiration time) claim is a Unix timestamp after which the token must be rejected. PyJWT checks it automatically during decode (when exp is present) and raises ExpiredSignatureError once the current time passes it.

"""02 · ``ExpiredSignatureError`` — the token's time is up.

The ``exp`` (expiration time) claim is a Unix timestamp after which the token must
be rejected. PyJWT checks it automatically during ``decode`` (when ``exp`` is
present) and raises ``ExpiredSignatureError`` once the current time passes it.

We make this happen *deliberately* by issuing a token that already expired one

    /home/astro/catalyst/jwt-test/.venv/bin/python \

from datetime import UTC, datetime, timedelta

import jwt

SECRET = "teaching-secret-key-with-at-least-32-bytes!"


def main() -> None:
    now = datetime.now(UTC)  # always timezone-aware!

    # exp one hour in the PAST -> already expired.
    token = jwt.encode(
        {"user": "grace", "exp": now - timedelta(hours=1)},
        SECRET,
        algorithm="HS256",
    )
    print("Issued a token that expired 1 hour ago.")
    print()

    try:
        jwt.decode(token, SECRET, algorithms=["HS256"])
    except jwt.ExpiredSignatureError as e:
        print(f"❌ Caught {type(e).__name__}: {e}")
        print("   Meaning: the 'exp' timestamp is in the past. Reject the token.")
    else:
        print("Unexpected: token verified (it should have been expired).")

    print()
    print("✅ PyJWT enforces 'exp' for you — no manual time math needed.")


if __name__ == "__main__":
    main()

import jwt

RIGHT_SECRET = "the-real-signing-secret-padded-to-32-bytes!"
WRONG_SECRET = "an-attacker-guess-padded-to-at-least-32-byte"

    # Sanity: the right secret still works.
    claims = jwt.decode(token, RIGHT_SECRET, algorithms=["HS256"])
    print(f"✅ With the correct secret it verifies fine: {claims}")

04 · DecodeError — the token is malformed.

Before PyJWT can even check a signature, the string has to look like a JWT: three base64url segments joined by dots, with a valid JSON header and payload. Hand it "not.a.jwt" or other garbage and it fails structurally with DecodeError — distinct from a signature that's present but wrong (InvalidSignatureError) or a token that's well-formed but expired (ExpiredSignatureError).

05 · InvalidAudienceError — this token isn't meant for you.

The aud (audience) claim names the intended recipient(s). When you call jwt.decode(..., audience=...), PyJWT checks that your expected audience is listed in the token's aud. If it isn't, you get InvalidAudienceError.

This stops a token minted for Service A from being replayed against Service B — even though both might trust the same issuer/key.

Two cases shown: - mismatch (token aud = "service-a", we expect "service-b") -> error; - match -> success.

The nbf (not before) claim is the mirror image of exp: a Unix timestamp before which the token must be rejected. It's used for tokens that should only activate in the future (scheduled access, delayed grants). Decode such a token too early and PyJWT raises ImmatureSignatureError.

07 · leeway — tolerating small clock skew.

Real clocks drift. A token that expired 5 seconds ago might be perfectly fine to accept if the issuer's clock was simply a hair ahead of yours. PyJWT's leeway argument adds a grace window (in seconds, or a timedelta) to the time-based checks (exp and nbf), so just-expired or just-premature tokens are still accepted.

This script issues a token that expired 5 seconds ago and decodes it two ways: - WITHOUT leeway -> ExpiredSignatureError; - WITH leeway=10 -> accepted (5s < 10s grace).

⚠️ Keep leeway small (a few seconds to a minute). It directly extends how long an expired token remains usable.

"""07 · ``leeway`` — tolerating small clock skew.

Real clocks drift. A token that expired 5 seconds ago might be perfectly fine to
accept if the issuer's clock was simply a hair ahead of yours. PyJWT's ``leeway``
argument adds a grace window (in seconds, or a ``timedelta``) to the time-based
checks (``exp`` and ``nbf``), so *just*-expired or *just*-premature tokens are
still accepted.

This script issues a token that expired 5 seconds ago and decodes it two ways:
    - WITHOUT leeway  -> ExpiredSignatureError;
    - WITH leeway=10  -> accepted (5s < 10s grace).

⚠️ Keep leeway small (a few seconds to a minute). It directly extends how long an
expired token remains usable.

Run:
    /home/astro/catalyst/jwt-test/.venv/bin/python \
        pyjwt-course/12-validation-errors-and-leeway/07_leeway.py
"""

from datetime import UTC, datetime, timedelta

import jwt

SECRET = "teaching-secret-key-with-at-least-32-bytes!"


def main() -> None:
    now = datetime.now(UTC)

    # Expired just 5 seconds ago.
    token = jwt.encode(
        {"user": "mallory", "exp": now - timedelta(seconds=5)},
        SECRET,
        algorithm="HS256",
    )
    print("Token expired 5 seconds ago.")
    print()

    # Side A: no leeway -> rejected.
    print("A) decode WITHOUT leeway:")
    try:
        jwt.decode(token, SECRET, algorithms=["HS256"])
    except jwt.ExpiredSignatureError as e:
        print(f"   ❌ {type(e).__name__}: {e}")
    print()

    # Side B: 10 seconds of leeway -> accepted.
    print("B) decode WITH leeway=10 seconds:")
    claims = jwt.decode(token, SECRET, algorithms=["HS256"], leeway=10)
    print(f"   ✅ accepted within grace window: {claims}")
    print()

    print("✅ leeway absorbs small clock skew — use sparingly (seconds, not hours).")


if __name__ == "__main__":
    main()

"""08 · A robust, reusable token validator.

Pulling the whole module together: a single ``validate(token)`` function that
returns a tuple ``(ok, result)`` instead of letting exceptions escape. On success
``result`` is the claims dict; on failure it's a friendly explanation. We also map
each failure to an HTTP-like status, the way an API gateway would.

The try/except *ladder* matters: order matters because the exceptions are
subclasses of one another. We catch the **specific** cases first and the
**general** ``InvalidTokenError`` last, so each failure gets its precise message
while nothing slips through unhandled.

Run:
    /home/astro/catalyst/jwt-test/.venv/bin/python \
        pyjwt-course/12-validation-errors-and-leeway/08_robust_validator.py
"""

from datetime import UTC, datetime, timedelta

import jwt

SECRET = "teaching-secret-key-with-at-least-32-bytes!"
AUDIENCE = "my-api"


def validate(token: str) -> tuple[bool, dict | str, int]:
    """Validate a token. Returns (ok, claims_or_reason, http_status)."""
    try:
        claims = jwt.decode(
            token,
            SECRET,
            algorithms=["HS256"],
            audience=AUDIENCE,
            options={"require": ["exp"]},  # demand an expiry
        )
        return True, claims, 200

    # --- specific cases first (most-derived -> least-derived) ---
    except jwt.ExpiredSignatureError:
        return False, "Token has expired — please re-authenticate.", 401
    except jwt.ImmatureSignatureError:
        return False, "Token is not valid yet (nbf in the future).", 401
    except jwt.InvalidAudienceError:
        return False, "Token audience mismatch — not issued for this service.", 403
    except jwt.InvalidIssuerError:
        return False, "Token issuer is not trusted.", 403
    except jwt.MissingRequiredClaimError as e:
        return False, f"Token is missing a required claim: {e}.", 400
    except jwt.InvalidSignatureError:
        return False, "Token signature is invalid — possible tampering.", 401
    except jwt.DecodeError:
        return False, "Token is malformed and cannot be decoded.", 400
    # --- catch-all for anything else in the JWT family ---
    except jwt.InvalidTokenError as e:
        return False, f"Token is invalid: {e}", 401


def _make(payload: dict) -> str:
    return jwt.encode(payload, SECRET, algorithm="HS256")


def main() -> None:
    now = datetime.now(UTC)
    good_base = {"sub": "u1", "aud": AUDIENCE, "exp": now + timedelta(hours=1)}

    cases = {
        "valid token": _make(good_base),
        "expired token": _make({**good_base, "exp": now - timedelta(hours=1)}),
        "wrong audience": _make({**good_base, "aud": "other-api"}),
        "missing exp": jwt.encode({"sub": "u1", "aud": AUDIENCE}, SECRET, algorithm="HS256"),
        "future nbf": _make({**good_base, "nbf": now + timedelta(hours=1)}),
        "tampered sig": _make(good_base)[:-3] + "xxx",
        "malformed": "not.a.jwt",
        "wrong key": jwt.encode(good_base, "different-secret-padded-to-32-plus-bytes!", algorithm="HS256"),
    }

    print(f"{'case':<16} {'status':>6}  result")
    print("-" * 70)
    for name, tok in cases.items():
        ok, result, status = validate(tok)
        shown = result if isinstance(result, str) else f"claims OK (sub={result.get('sub')})"
        flag = "✅" if ok else "❌"
        print(f"{name:<16} {status:>6}  {flag} {shown}")

    print()
    print("✅ One validate() funnels every failure mode into a clean (ok, reason, status).")


if __name__ == "__main__":
    main()
