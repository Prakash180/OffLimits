Module 15 · Real-World FastAPI & OAuth2 / OIDC

🧠 Mental Model — Behind the Scenes

Production auth is a relationship between three roles that never fully trust each other: the authorization server (the IdP) that mints tokens, the client app that carries them, and the resource server (your API) that verifies them. The tokens flowing between them come in three distinct flavors, and conflating them is the most common architectural mistake. An access token is a short-lived key to call an API — the resource server checks its signature, iss, aud, and exp on every request. A refresh token is a longer-lived, separately-keyed credential whose only job is to obtain a fresh access token when the old one expires; an API must never accept it in the access slot. An id_token is an OIDC artifact about who the user is — it's for the client, validated against aud == client_id (and a nonce), not a license to call APIs.

On the API side, the verification gate is plumbed into the framework as a dependency. In FastAPI you write one Depends(get_current_user) that extracts the Authorization: Bearer <token> header, runs jwt.decode with pinned algorithms, audience, and issuer, and either returns the claims or raises 401. Every protected route reuses that single gate — authentication becomes a one-liner per endpoint. Crucially, authentication and authorization are two separate gates: a valid signature proves who the caller is (→ 401 if it fails), while a scope or role check decides what they may do (→ 403 if insufficient). The scope claim is OAuth2's permission grammar; a require_scope("read") guard enforces it after identity is established.

The deepest pattern in the module is JWKS-based verification, which is how the real internet checks tokens it has never seen. The resource server doesn't share a secret with the IdP — instead it fetches the IdP's public keys from a published jwks_uri, selects the right one by the token's kid, and verifies the RS256 signature. PyJWT packages this as PyJWKClient: point it at the keys URL, call get_signing_key_from_jwt(token), and pass the result to jwt.decode(token, signing_key.key, algorithms=["RS256"], audience=..., issuer=...). This is exactly the Microsoft Entra ID pattern — https://login.microsoftonline.com/{tenant}/discovery/v2.0/keys for the JWKS and .../v2.0 for the issuer. Module 15 runs an offline mirror of this flow (local keys, local JWKS, real kid selection) so it works with no network, keeping the live Azure code in comments. For a fully runnable local issuer that speaks OAuth2/OIDC end-to-end, the course also ships a local identity provider in module 16.

🔍 A concrete analogy

An access token is a day-pass wristband to the theme park rides — checked at every gate, expires at closing. A refresh token is your season membership card kept safe at home; you don't wave it at rides, you only show it at the booth to get tomorrow's wristband. An id_token is your photo ID that tells the front desk who you are, not a ride pass. And JWKS is the park's public registry of valid wristband patterns posted at the entrance — every gate consults it (by serial number / kid) instead of radioing headquarters.

⚙️ What actually happens when you run the code

  1. The auth server signs an access token (RS256) with realistic claims — iss, sub, aud, iat, exp, and scope — stamping its kid into the header.
  2. The client sends it to the API as Authorization: Bearer <token>.
  3. A FastAPI dependency extracts the token from the header (or raises 401 if missing/malformed).
  4. The resource server obtains the IdP's public key — locally by kid in the offline demo, or via PyJWKClient.get_signing_key_from_jwt in the Entra pattern.
  5. jwt.decode(token, key, algorithms=["RS256"], audience=CLIENT_ID, issuer=ISSUER) verifies signature + aud + iss + exp in one call.
  6. A scope/role check runs after identity is confirmed — insufficient scope → 403, never 401.
  7. When the access token expires, the client presents its refresh token to mint a new one without re-authenticating.

👀 What to notice when you run the examples

  • 02_verify_access_token.py: dropping audience= or issuer= lets a token from another app sail through — the checks are not optional.
  • 03_access_and_refresh_tokens.py: an access token offered in the refresh slot (or vice versa) is rejected — they're keyed/typed separately.
  • 04_fastapi_dependency.py: httpx isn't installed here, so TestClient falls back to calling the dependency directly — still exercising valid/invalid/missing paths and exiting 0.
  • 07_entra_id_validation_pattern.py: the offline run mirrors the exact PyJWKClient + jwt.decode sequence used against live Azure (see the commented validate_token_azure()).

⚠️ Common misconceptions

  • "Verifying the signature is enough." You must also pin audience= and issuer=, or a valid token from a different app/tenant passes.
  • "An id_token can call my API." It's identity for the client; APIs should accept access tokens and check aud.
  • "scope is identity." Scope is permission (what the app may do); sub is identity (who the user is) — keep authN and authZ separate.
  • "Trust the kid/jku the token supplies." Always resolve keys against a known JWKS / allowlist, never a URL the token itself dictates.

🟦 The Microsoft Entra ID pattern (script 07)

This is the production code shape, identical to the repo's tests/validate.py:

from jwt import PyJWKClient

JWKS_URL = f"https://login.microsoftonline.com/{TENANT_ID}/discovery/v2.0/keys"
ISSUER   = f"https://login.microsoftonline.com/{TENANT_ID}/v2.0"

jwk_client  = PyJWKClient(JWKS_URL)                       # downloads + caches keys
signing_key = jwk_client.get_signing_key_from_jwt(token)  # picks the key by 'kid'
claims = jwt.decode(
    token, signing_key.key, algorithms=["RS256"],
    audience=CLIENT_ID, issuer=ISSUER,
)

🔑 Key takeaways

  1. Issue rich, scoped, time-boxed tokens — iss, sub, aud, iat, exp, scope. The verifier enforces every one.
  2. Access vs. refresh. Keep access tokens short; renew with a separately keyed refresh token. Never accept an access token in the refresh slot.
  3. Protect routes with a dependency. One Depends(get_current_user) gates a route; invalid → 401.
  4. Separate authN from authZ. A valid signature proves who; scope/role checks decide what they may do → 403 when insufficient.
  5. JWKS + kid is how the internet verifies tokens. OIDC providers and Entra ID publish public keys; clients select by kid and pin RS256 + aud + iss.

⚠️ Pitfalls

  • Verifying signature but forgetting audience=/issuer= → tokens from another app/tenant slip through.
  • Long-lived access tokens with no refresh strategy.
  • Confusing scope (what the app may do) with identity (sub).
  • Trusting an id_token without checking aud == client_id and the nonce.
  • Fetching keys from a kid/jku the token itself supplies — always validate kid against a known JWKS / allowlist.

"""
01 · Issuing an access token — the authorization server's job
=============================================================

An OAuth2 *authorization server* mints access tokens after a user authenticates.
A realistic access token carries standard registered claims:

* ``iss`` (issuer)   — who minted it (your auth server URL).
* ``sub`` (subject)  — the user/principal id.
* ``aud`` (audience) — which API/resource the token is FOR.
* ``iat`` (issued at), ``nbf`` (not before), ``exp`` (expiry) — the time window.
* ``scope``          — space-delimited OAuth2 permissions.
* plus app claims (e.g. ``roles``).

This module's verifier (script 02) checks these. We show both an HS256 issuer
(shared secret) and an RS256 issuer (private key), since real systems use both.

Run:
    /home/astro/catalyst/jwt-test/.venv/bin/python \
        pyjwt-course/15-real-world-fastapi-oauth/01_issue_access_token.py
"""

from datetime import UTC, datetime, timedelta

import jwt
from cryptography.hazmat.primitives import serialization
from cryptography.hazmat.primitives.asymmetric import rsa

ISSUER = "https://auth.example.com"
AUDIENCE = "https://api.example.com"
HS_SECRET = "auth-server-hs256-secret-at-least-32-bytes!!"


def issue_access_token_hs256(
    subject: str, scope: str, ttl_seconds: int = 900
) -> str:
    """Issue an HS256 access token with realistic OAuth2 claims."""
    now = datetime.now(UTC)
    claims = {
        "iss": ISSUER,
        "sub": subject,
        "aud": AUDIENCE,
        "iat": now,
        "nbf": now,
        "exp": now + timedelta(seconds=ttl_seconds),
        "scope": scope,
        "token_type": "access",
    }
    return jwt.encode(claims, HS_SECRET, algorithm="HS256")


def issue_access_token_rs256(
    private_pem: str, subject: str, scope: str, kid: str, ttl_seconds: int = 900
) -> str:
    """Issue an RS256 access token; include a 'kid' so verifiers pick the key."""
    now = datetime.now(UTC)
    claims = {
        "iss": ISSUER,
        "sub": subject,
        "aud": AUDIENCE,
        "iat": now,
        "nbf": now,
        "exp": now + timedelta(seconds=ttl_seconds),
        "scope": scope,
        "token_type": "access",
    }
    return jwt.encode(claims, private_pem, algorithm="RS256", headers={"kid": kid})


def main() -> None:
    print("=" * 72)
    print("HS256 access token (shared-secret issuer)")
    print("=" * 72)
    hs = issue_access_token_hs256("user-123", scope="profile email read:reports")
    print(f"token: {hs}")
    # Decode just to display the claims we minted (verification covered in 02).
    print("claims:", jwt.decode(hs, HS_SECRET, algorithms=["HS256"], audience=AUDIENCE))
    print()

    print("=" * 72)
    print("RS256 access token (private-key issuer, with kid header)")
    print("=" * 72)
    key = rsa.generate_private_key(public_exponent=65537, key_size=2048)
    private_pem = key.private_bytes(
        encoding=serialization.Encoding.PEM,
        format=serialization.PrivateFormat.PKCS8,
        encryption_algorithm=serialization.NoEncryption(),
    ).decode()
    public_pem = key.public_key().public_bytes(
        encoding=serialization.Encoding.PEM,
        format=serialization.PublicFormat.SubjectPublicKeyInfo,
    ).decode()
    rs = issue_access_token_rs256(private_pem, "user-123", "profile admin", kid="key-1")
    print(f"token: {rs[:60]}...")
    print(f"header: {jwt.get_unverified_header(rs)}")
    print("claims:", jwt.decode(rs, public_pem, algorithms=["RS256"], audience=AUDIENCE))

    print("\nNext: script 02 verifies these tokens, enforcing iss/aud/exp.")


if __name__ == "__main__":
    main()

02 Verify Access Token02_verify_access_token.py ▾

A resource server (your API) receives an access token and must validate it before trusting any claim. A correct verifier:

  1. Pins the algorithm: algorithms=["HS256"] (or RS256).
  2. Checks the signature (PyJWT does this with the key).
  3. Enforces aud — the token must be FOR this API (audience=...).
  4. Enforces iss — the token must be FROM our trusted issuer (issuer=...).
  5. Enforces exp/nbf — automatically, and we require the key ones.

We show a valid token passing and a battery of bad tokens being rejected with specific, catchable PyJWT exceptions.

"""
02 · Verifying an access token — the resource server's job
==========================================================

A *resource server* (your API) receives an access token and must validate it
before trusting any claim. A correct verifier:

1. Pins the algorithm: ``algorithms=["HS256"]`` (or RS256).
2. Checks the signature (PyJWT does this with the key).
3. Enforces ``aud`` — the token must be FOR this API (``audience=...``).
4. Enforces ``iss`` — the token must be FROM our trusted issuer (``issuer=...``).
5. Enforces ``exp``/``nbf`` — automatically, and we ``require`` the key ones.

We show a valid token passing and a battery of bad tokens being rejected with
specific, catchable PyJWT exceptions.

Run:
    /home/astro/catalyst/jwt-test/.venv/bin/python \
        pyjwt-course/15-real-world-fastapi-oauth/02_verify_access_token.py
"""

from datetime import UTC, datetime, timedelta

import jwt

ISSUER = "https://auth.example.com"
AUDIENCE = "https://api.example.com"
SECRET = "auth-server-hs256-secret-at-least-32-bytes!!"


def issue(subject: str, **overrides) -> str:
    now = datetime.now(UTC)
    claims = {
        "iss": ISSUER,
        "sub": subject,
        "aud": AUDIENCE,
        "iat": now,
        "nbf": now,
        "exp": now + timedelta(minutes=15),
        "scope": "read",
    }
    claims.update(overrides)
    return jwt.encode(claims, SECRET, algorithm="HS256")


def verify_access_token(token: str) -> dict:
    """Validate signature + iss + aud + exp; return trusted claims or raise."""
    return jwt.decode(
        token,
        SECRET,
        algorithms=["HS256"],  # pin the algorithm — never trust the header
        audience=AUDIENCE,  # reject tokens minted for another API
        issuer=ISSUER,  # reject tokens from another issuer
        options={"require": ["exp", "iss", "aud", "sub"]},
    )


def main() -> None:
    print("=" * 72)
    print("VALID token -> accepted")
    print("=" * 72)
    good = issue("user-123")
    print(f"claims: {verify_access_token(good)}\n")

    print("=" * 72)
    print("INVALID tokens -> each rejected with a specific exception")
    print("=" * 72)

    cases = {
        "wrong audience": issue("user-123", aud="https://other-api.example.com"),
        "wrong issuer": issue("user-123", iss="https://evil.example.com"),
        "expired": issue(
            "user-123",
            iat=datetime.now(UTC) - timedelta(hours=2),
            exp=datetime.now(UTC) - timedelta(hours=1),
        ),
        "tampered signature": issue("user-123")[:-3] + "xyz",
        "wrong secret": jwt.encode(
            {
                "iss": ISSUER,
                "sub": "mallory",
                "aud": AUDIENCE,
                "exp": datetime.now(UTC) + timedelta(minutes=5),
            },
            "attacker-secret-attacker-secret-attacker!",
            algorithm="HS256",
        ),
    }

    for label, token in cases.items():
        try:
            verify_access_token(token)
            print(f"  {label:20} -> UNEXPECTEDLY ACCEPTED")
        except jwt.InvalidTokenError as exc:
            print(f"  {label:20} -> rejected: {type(exc).__name__}")

    print("\nEvery untrusted token is rejected. Trust only verified claims.")


if __name__ == "__main__":
    main()

03 Access And Refresh Tokens03_access_and_refresh_tokens.py ▾

Access tokens should be SHORT-lived (minutes) so a leaked one expires quickly. But you don't want users logging in every 15 minutes. The standard answer:

  • Access token — short TTL (e.g. 15 min), sent on every API call.
  • Refresh token — long TTL (e.g. 30 days), sent ONLY to the auth server to mint a new access token when the old one expires.

We distinguish them with a token_type claim and (in real systems) often a separate signing key/audience. The refresh() function validates a refresh token and issues a fresh access token — refusing to accept an access token in the refresh slot (a common confused-deputy mistake).

from datetime import UTC, datetime, timedelta

import jwt

ISSUER = "https://auth.example.com"
AUDIENCE = "https://api.example.com"
ACCESS_SECRET = "access-token-signing-secret-32-bytes-long!!"
REFRESH_SECRET = "refresh-token-signing-secret-32-bytes-long!"  # separate key!

ACCESS_TTL = timedelta(minutes=15)
REFRESH_TTL = timedelta(days=30)


def issue_access_token(subject: str, scope: str) -> str:
    now = datetime.now(UTC)
    return jwt.encode(
        {
            "iss": ISSUER,
            "sub": subject,

    """Authorization guard: raise PermissionDenied unless `needed` is granted."""
    granted = token_scopes(claims)

def build_local_jwks(public_key, kid: str) -> dict:
    """Serialise an RSA public key into a one-key JWKS, like a provider's."""
    jwk = json.loads(RSAAlgorithm.to_jwk(public_key))
    jwk.update({"kid": kid, "use": "sig", "alg": "RS256"})

    """Pick the signing key from a JWKS whose 'kid' matches the token header."""
    keyset = jwt.PyJWKSet.from_dict(jwks)
    for key in keyset.keys:

=====================================================================

This is the real-world pattern used to validate access/id tokens from Microsoft
Entra ID (formerly Azure AD). It is exactly what this repo's
``tests/validate.py`` does:

    JWKS_URL = https://login.microsoftonline.com/{TENANT_ID}/discovery/v2.0/keys
    ISSUER   = https://login.microsoftonline.com/{TENANT_ID}/v2.0

``PyJWKClient`` downloads Microsoft's public keys, caches them, and uses the
token's ``kid`` to pick the right one. You then verify with RS256, pinning the
audience (your app/client id) and the issuer (your tenant).

steps — local RS256 key, local JWKS, ``kid`` selection — and keep the genuine
Azure version in comments.

def validate_token_azure(access_token: str) -> dict:
    """The production Entra ID validation. Requires network; shown for truth.

    This is intentionally NOT called in the offline demo below, but it IS the
    pattern you ship. It is identical in shape to repo tests/validate.py.

        signing_key.key,

    )

def get_signing_key_from_local_jwks(token: str, jwks: dict):
    """Local stand-in for PyJWKClient.get_signing_key_from_jwt: select by kid."""
    kid = jwt.get_unverified_header(token)["kid"]
    keyset = jwt.PyJWKSet.from_dict(jwks)
    for key in keyset.keys:
        if key.key_id == kid:
            return key  # a PyJWK; use .key for the underlying public key
    raise jwt.PyJWKClientError(f"no signing key for kid={kid!r}")

"""
08 · Capstone — the full request auth lifecycle, end to end
===========================================================

This ties the whole course together. We follow one realistic request through
every stage of a token's life:

    MINT  -> TRANSMIT -> RECEIVE -> VERIFY -> AUTHORIZE -> SERVE

* **Mint**      — the auth server issues an RS256 access token with realistic
  claims (iss, sub, aud, exp, scope, roles) and a ``kid`` header.
* **Transmit**  — the client sends it as an ``Authorization: Bearer <token>``
  header string (we literally build that header line).
* **Receive**   — the API extracts the raw token from the header.
* **Verify**    — the API selects the key by ``kid`` from its JWKS and validates
  signature + iss + aud + exp.
* **Authorize** — the API checks the required scope/role for the endpoint.
* **Serve**     — only now does it return data.

Every stage prints what it did, so you can watch trust being established.

Run:
    /home/astro/catalyst/jwt-test/.venv/bin/python \
        pyjwt-course/15-real-world-fastapi-oauth/08_putting_it_all_together.py
"""

import json
from datetime import UTC, datetime, timedelta

import jwt
from cryptography.hazmat.primitives import serialization
from cryptography.hazmat.primitives.asymmetric import rsa
from jwt.algorithms import RSAAlgorithm

ISSUER = "https://auth.example.com"
AUDIENCE = "https://api.example.com"
KID = "auth-key-2026-06"


class AuthError(Exception):
    """401 — token missing/invalid."""


class PermissionDenied(Exception):
    """403 — valid token but insufficient scope/role."""


# --------------------------------------------------------------------------
# AUTH SERVER
# --------------------------------------------------------------------------
def auth_server_mint(private_pem: str, subject: str, scope: str, roles: list[str]) -> str:
    now = datetime.now(UTC)
    return jwt.encode(
        {
            "iss": ISSUER,
            "sub": subject,
            "aud": AUDIENCE,
            "iat": now,
            "nbf": now,
            "exp": now + timedelta(minutes=15),
            "scope": scope,
            "roles": roles,
        },
        private_pem,
        algorithm="RS256",
        headers={"kid": KID},
    )


# --------------------------------------------------------------------------
# RESOURCE SERVER (API)
# --------------------------------------------------------------------------
def extract_bearer(authorization_header: str) -> str:
    scheme, _, token = authorization_header.partition(" ")
    if scheme.lower() != "bearer" or not token:
        raise AuthError("malformed Authorization header")
    return token


def select_key(jwks: dict, token: str):
    kid = jwt.get_unverified_header(token)["kid"]
    for key in jwt.PyJWKSet.from_dict(jwks).keys:
        if key.key_id == kid:
            return key.key
    raise AuthError(f"unknown kid {kid!r}")


def verify(token: str, jwks: dict) -> dict:
    try:
        return jwt.decode(
            token,
            select_key(jwks, token),
            algorithms=["RS256"],
            audience=AUDIENCE,
            issuer=ISSUER,
            options={"require": ["exp", "iss", "aud", "sub"]},
        )
    except jwt.InvalidTokenError as exc:
        raise AuthError(f"token verification failed: {exc}") from exc


def authorize(claims: dict, *, scope: str, role: str) -> None:
    if scope not in set(claims.get("scope", "").split()):
        raise PermissionDenied(f"missing scope {scope!r}")
    if role not in claims.get("roles", []):
        raise PermissionDenied(f"missing role {role!r}")


def handle_request(authorization_header: str, jwks: dict) -> dict:
    """The API endpoint: the full receive->verify->authorize->serve pipeline."""
    token = extract_bearer(authorization_header)
    print(f"  [RECEIVE]   extracted token: {token[:32]}...")
    claims = verify(token, jwks)
    print(f"  [VERIFY]    signature+iss+aud+exp OK; sub={claims['sub']}")
    authorize(claims, scope="write:reports", role="editor")
    print(f"  [AUTHORIZE] scope+role OK ({claims['scope']!r}, {claims['roles']})")
    return {"report_id": 42, "status": "created", "owner": claims["sub"]}


def main() -> None:
    # Provider key + JWKS (the API knows the public keys, not the private one).
    key = rsa.generate_private_key(public_exponent=65537, key_size=2048)
    private_pem = key.private_bytes(
        encoding=serialization.Encoding.PEM,
        format=serialization.PrivateFormat.PKCS8,
        encryption_algorithm=serialization.NoEncryption(),
    ).decode()
    jwk = json.loads(RSAAlgorithm.to_jwk(key.public_key()))
    jwk.update({"kid": KID, "use": "sig", "alg": "RS256"})
    jwks = {"keys": [jwk]}

    print("=" * 72)
    print("SCENARIO A — an EDITOR creates a report (happy path)")
    print("=" * 72)
    print("[MINT]      auth server issues token for editor 'alice'")
    token = auth_server_mint(private_pem, "alice", "profile write:reports", ["editor"])
    header_line = f"Authorization: Bearer {token}"
    print(f"[TRANSMIT]  client sends header: {header_line[:48]}...")
    result = handle_request(header_line.removeprefix("Authorization: "), jwks)
    print(f"  [SERVE]     200 OK -> {result}\n")

    print("=" * 72)
    print("SCENARIO B — a READER tries to create a report (403)")
    print("=" * 72)
    print("[MINT]      auth server issues token for reader 'bob'")
    bob = auth_server_mint(private_pem, "bob", "profile read:reports", ["viewer"])
    try:
        handle_request(f"Bearer {bob}", jwks)
    except PermissionDenied as exc:
        print(f"  [AUTHORIZE] 403 Forbidden -> {exc}\n")

    print("=" * 72)
    print("SCENARIO C — a forged/garbage token (401)")
    print("=" * 72)
    try:
        handle_request("Bearer not.a.realtoken", jwks)
    except AuthError as exc:
        print(f"  [VERIFY]    401 Unauthorized -> {exc}\n")

    print("=" * 72)
    print("LIFECYCLE: mint -> transmit -> receive -> verify -> authorize -> serve")
    print("Identity (verify) and permission (authorize) are SEPARATE gates. You")
    print("passed both only in Scenario A. That is production JWT auth in full.")
    print("=" * 72)


if __name__ == "__main__":
    main()
