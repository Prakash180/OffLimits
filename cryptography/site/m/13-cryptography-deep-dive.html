Module 13 · Cryptography Deep Dive

🧠 Mental Model — Behind the Scenes

Strip the JSON costume off any JWT and you find three classic cryptographic primitives stacked on top of each other: hashing → MACs → digital signatures. A hash like SHA-256 is a one-way function: feed it any number of bytes and it spits out a fixed-size digest (32 bytes for SHA-256) that is infeasible to reverse. Flip a single input bit and roughly half the output bits flip — the avalanche effect. A hash proves the bytes didn't change by accident: that's integrity. But it proves nothing about who produced them, because anyone can recompute a hash. Integrity without authenticity is not security.

To add authenticity you mix a secret into the hash. That's an HMAC (Hash-based Message Authentication Code), and HMAC-SHA256 is literally the engine behind HS256. The reveal that makes JWTs click: an HS256 signature is exactly base64url( HMAC-SHA256( "header.payload", secret ) ). You can recompute it by hand with Python's hmac module and watch it come out byte-for-byte identical to the token's third segment. There is no magic — the verifier simply recomputes the same HMAC and compares with a constant-time check (hmac.compare_digest, never ==, to avoid timing leaks). An attacker without the secret can't produce a matching segment.

HMAC is symmetric: the same secret both signs and verifies, so everyone who can verify can also forge. That's fine inside one trust boundary but useless for the public internet. Digital signatures solve this with asymmetric key pairs: a private key signs, and a mathematically-linked public key verifies. The private key never leaves the issuer; the public key can be published to the entire world (that's what JWKS does). This is why RS256/ES256/PS256/EdDSA let any client verify a provider's tokens while being unable to mint one. The security rests on trapdoor functions — operations easy one way but infeasible to reverse (integer factoring for RSA, the discrete-log problem on elliptic curves for ECDSA/EdDSA).

Finally, the same key wears different clothes depending on context: PEM (base64 text with -----BEGIN----- headers, what PyJWT usually wants), DER (the raw binary encoding underneath PEM), and JWK (the JSON form served by JWKS endpoints). Converting between them never changes the key — only its packaging.

🔍 A concrete analogy

A hash is a tamper-evident seal: break it and you can tell something changed, but anyone can buy the same seal. An HMAC is a seal pressed with a shared signet ring — only ring-holders can make or check it. A digital signature is a wax seal from a ring whose impression is published in the town square: everyone can confirm the impression matches the public pattern, but only the ring's owner can press a genuine one. Publishing the impression (public key) never lets anyone carve the ring (private key).

⚙️ What actually happens when you run the code

  1. SHA-256 reduces arbitrary input to a fixed 32-byte digest; changing one character produces a wildly different digest (avalanche).
  2. A demo shows a bare hash gives integrity but not authenticity — an attacker just recomputes it over their own forged payload.
  3. PyJWT mints an HS256 token; the script splits off header.payload.signature.
  4. Python's hmac.new(secret, "header.payload", sha256).digest() is computed independently and base64url-encoded without padding.
  5. The hand-computed value is compared against the token's third segment — they match exactly, proving HS256 == base64url(HMAC-SHA256).
  6. An RSA private key signs a message and the public key verifies it, demonstrating the asymmetric (sign=private / verify=public) split behind RS256.
  7. One public key is serialized three ways — PEM, DER (hex), JWK — showing they're the same key in different formats.

⚠️ Common misconceptions

  • "Hashing is encryption." No — hashing is one-way; there is no "unhash" and you can't recover a payload from a signature.
  • "A hash alone authenticates the sender." It only proves integrity; without a secret or private key, anyone can recompute it.
  • "Publishing a public key is risky." Trapdoor math makes deriving the private key infeasible — publishing it is the intended design.
  • "A different signature each run means it's broken." ECDSA and RSA-PSS are intentionally randomized; identical-every-time is not required.

🔬 Module 13 · Cryptography Deep Dive

"A JWT is cryptography wearing a JSON costume."

Every signing algorithm in PyJWT — HS256, RS256, ES256, PS256, EdDSA — is a thin wrapper around classic cryptographic primitives. This module strips the costume off and rebuilds the machinery from the ground up: hashes → MACs → digital signatures → key formats → the full algorithm zoo.

By the end you'll be able to recompute an HS256 signature by hand and explain exactly why you can publish an RSA public key to the entire internet.

🔑 Key takeaways

  1. HS256 is base64url(HMAC-SHA256(header.payload, secret)). Script 03 proves it byte-for-byte. Once you see it, JWTs stop being magic.
  2. Hash ≠ MAC ≠ signature. A hash gives integrity; a MAC (HMAC) adds authenticity with a shared secret; a signature adds authenticity with a private key that the verifier never sees.
  3. Sign = private, verify = public. This single sentence explains why identity providers can publish keys via JWKS and the world can verify their tokens without ever being able to forge one.
  4. Trapdoor functions (factoring for RSA, discrete log for EC) make it infeasible to derive the private key from the public key.
  5. PEM / DER / JWK are the same key, different clothes. JWKS endpoints serve JWK; PyJWT arguments usually want PEM; DER is the underlying binary.

⚠️ Pitfalls

  • Don't confuse hashing with encryption. Hashing is one-way; there is no "unhash". You cannot recover a payload from a signature.
  • Never compare signatures with ==. Use hmac.compare_digest to avoid timing side-channels (PyJWT does this for you internally).
  • HMAC keys should be ≥ 32 bytes for SHA-256 (RFC 7518 §3.2). Short secrets trigger PyJWT's InsecureKeyLengthWarning.
  • ECDSA and RSA-PSS signatures are randomised — the same input yields a different signature each run. That's by design, not a bug.

01 Hashing Sha201_hashing_sha2.py ▾

A cryptographic hash function takes an input of ANY size and produces a fixed-size "digest". JWTs lean on the SHA-2 family (SHA-256/384/512): the "256" in HS256 / RS256 / ES256 literally means "SHA-256".

Three properties we demonstrate below:

  1. One-way (preimage resistance) — given a digest you cannot feasibly recover the input. Hashing is NOT encryption; there is no "unhash".
  2. Fixed output size — a 3-byte input and a 3-megabyte input both produce a 256-bit (32-byte / 64 hex-char) digest for SHA-256.
  3. Avalanche effect — flipping a single character changes ~half the output bits, producing a totally different-looking digest.

"""
01 · Hashing with SHA-2 — the foundation under every JWT signature
===================================================================

A *cryptographic hash function* takes an input of ANY size and produces a
fixed-size "digest". JWTs lean on the SHA-2 family (SHA-256/384/512): the "256"
in ``HS256`` / ``RS256`` / ``ES256`` literally means "SHA-256".

Three properties we demonstrate below:

1. **One-way (preimage resistance)** — given a digest you cannot feasibly
   recover the input. Hashing is NOT encryption; there is no "unhash".
2. **Fixed output size** — a 3-byte input and a 3-megabyte input both produce a
   256-bit (32-byte / 64 hex-char) digest for SHA-256.
3. **Avalanche effect** — flipping a single character changes ~half the output
   bits, producing a totally different-looking digest.

Run:
    /home/astro/catalyst/jwt-test/.venv/bin/python \
        pyjwt-course/13-cryptography-deep-dive/01_hashing_sha2.py
"""

import hashlib


def digest(algorithm: str, data: str) -> str:
    """Return the hex digest of ``data`` using the named SHA-2 algorithm."""
    h = hashlib.new(algorithm)
    h.update(data.encode("utf-8"))
    return h.hexdigest()


def hamming_distance_hex(a: str, b: str) -> int:
    """Count how many *bits* differ between two equal-length hex digests."""
    a_int = int(a, 16)
    b_int = int(b, 16)
    return bin(a_int ^ b_int).count("1")


def main() -> None:
    print("=" * 70)
    print("SHA-2 DIGESTS OF THE SAME MESSAGE")
    print("=" * 70)
    message = "The quick brown fox jumps over the lazy dog"
    print(f"Message: {message!r}\n")

    for algorithm in ("sha256", "sha384", "sha512"):
        d = digest(algorithm, message)
        # Output is fixed size regardless of input length.
        print(f"{algorithm.upper():8} -> {d}")
        print(f"{'':8}    ({len(d) * 4} bits, {len(d)} hex chars)\n")

    print("=" * 70)
    print("FIXED OUTPUT SIZE — tiny vs huge input, same digest length")
    print("=" * 70)
    tiny = "hi"
    huge = "A" * 3_000_000  # ~3 MB of data
    tiny_d = digest("sha256", tiny)
    huge_d = digest("sha256", huge)
    print(f"SHA-256 of {len(tiny)}-byte input        -> {tiny_d} ({len(tiny_d)} hex)")
    print(f"SHA-256 of {len(huge):,}-byte input -> {huge_d} ({len(huge_d)} hex)")
    print("Both digests are exactly 64 hex chars. Size in, fixed size out.\n")

    print("=" * 70)
    print("AVALANCHE EFFECT — change one character, get a new universe")
    print("=" * 70)
    original = "Attack at dawn"
    tampered = "Attack at dusk"  # changed 'aw' -> 'us' (a couple of chars)
    od = digest("sha256", original)
    td = digest("sha256", tampered)
    bits_changed = hamming_distance_hex(od, td)
    total_bits = len(od) * 4
    print(f"Original: {original!r}")
    print(f"  -> {od}")
    print(f"Tampered: {tampered!r}")
    print(f"  -> {td}")
    print(
        f"\nBits changed: {bits_changed}/{total_bits} "
        f"(~{bits_changed / total_bits:.0%}). A small input change "
        f"scrambles half the output."
    )

    print("\n" + "=" * 70)
    print("ONE-WAY: there is no hashlib.unsha256(). You cannot reverse a digest.")
    print("This integrity property is exactly what JWT signatures are built on.")
    print("=" * 70)


if __name__ == "__main__":
    main()

"""
02 · Why a plain hash isn't enough — integrity vs. authenticity
================================================================

A bare hash gives you **integrity**: if you have the message *and* its digest,
you can detect accidental corruption by re-hashing and comparing.

But a bare hash gives you NO **authenticity**. Anyone who can change the message
can simply recompute the hash to match. There is no secret involved, so the
digest proves nothing about *who* produced it.

    integrity   = "the bits didn't change by accident"
    authenticity = "the bits came from someone who holds a secret/key"

This script plays the attacker: we intercept a (message, hash) pair, rewrite the
message, recompute the hash, and the receiver's naive check still passes. This
is the motivation for **MACs** (next script: HMAC) and digital signatures.

Run:
    /home/astro/catalyst/jwt-test/.venv/bin/python \
        pyjwt-course/13-cryptography-deep-dive/02_why_hashes_arent_enough.py
"""

import hashlib


def sha256_hex(data: str) -> str:
    return hashlib.sha256(data.encode("utf-8")).hexdigest()


def receiver_accepts(message: str, claimed_hash: str) -> bool:
    """A naive receiver: trusts the message if SHA-256(message) == claimed_hash."""
    return sha256_hex(message) == claimed_hash


def main() -> None:
    print("=" * 70)
    print("STEP 1 — Alice sends a message plus its SHA-256 hash")
    print("=" * 70)
    alice_message = "Pay Bob $100"
    alice_hash = sha256_hex(alice_message)
    print(f"message      : {alice_message!r}")
    print(f"sha256(msg)  : {alice_hash}")
    print("Alice transmits BOTH over the wire.\n")

    print("=" * 70)
    print("STEP 2 — The receiver verifies (integrity check passes)")
    print("=" * 70)
    print(f"receiver accepts original? {receiver_accepts(alice_message, alice_hash)}\n")

    print("=" * 70)
    print("STEP 3 — Mallory (attacker) intercepts and tampers")
    print("=" * 70)
    # Mallory rewrites the message AND recomputes the hash. No secret needed.
    mallory_message = "Pay Mallory $10000"
    mallory_hash = sha256_hex(mallory_message)
    print(f"forged message: {mallory_message!r}")
    print(f"forged hash   : {mallory_hash}")
    print("Mallory replaces both fields and forwards them on.\n")

    print("=" * 70)
    print("STEP 4 — The naive receiver is fooled")
    print("=" * 70)
    fooled = receiver_accepts(mallory_message, mallory_hash)
    print(f"receiver accepts forgery? {fooled}  <-- DISASTER")
    print(
        "\nThe hash matched, so the receiver 'trusts' the message — but it came\n"
        "from an attacker. A plain hash proves integrity, NOT authenticity."
    )

    print("\n" + "=" * 70)
    print("THE FIX (preview)")
    print("=" * 70)
    print(
        "Mix a SECRET into the hash so only key-holders can produce a valid tag:\n"
        "  - shared secret  -> HMAC  (HS256)      [next script]\n"
        "  - private key    -> signature (RS256)  [script 05]\n"
        "Mallory has neither, so she can no longer forge a matching tag."
    )

03 HMAC From Scratch03_hmac_from_scratch.py ▾

The big reveal: an HS256 JWT signature is just an HMAC-SHA256, base64url- encoded. Nothing magic. In this script we:

  1. Build an HS256 JWT with PyJWT.
  2. Split it into its three dot-separated segments: header.payload.signature.
  3. Independently compute HMAC-SHA256 over the ASCII bytes of f"{header}.{payload}" using Python's hmac module + our secret.
  4. base64url-encode (no padding) our raw HMAC and show it is byte-for-byte identical to the token's third segment.

"""
03 · HMAC from scratch — demystifying the HS256 signature
==========================================================

The big reveal: an HS256 JWT signature is *just* an HMAC-SHA256, base64url-
encoded. Nothing magic. In this script we:

1. Build an HS256 JWT with PyJWT.
2. Split it into its three dot-separated segments: header.payload.signature.
3. Independently compute HMAC-SHA256 over the ASCII bytes of
   ``f"{header}.{payload}"`` using Python's ``hmac`` module + our secret.
4. base64url-encode (no padding) our raw HMAC and show it is byte-for-byte
   identical to the token's third segment.

That equality is the whole trick behind HS256. The verifier recomputes the same
HMAC and compares — an attacker without the secret cannot.

Run:
    /home/astro/catalyst/jwt-test/.venv/bin/python \
        pyjwt-course/13-cryptography-deep-dive/03_hmac_from_scratch.py
"""

import base64
import hashlib
import hmac

import jwt


def b64url_nopad(raw: bytes) -> str:
    """base64url-encode WITHOUT the trailing '=' padding (the JOSE convention)."""
    return base64.urlsafe_b64encode(raw).rstrip(b"=").decode("ascii")


def main() -> None:
    # 32+ bytes: RFC 7518 recommends an HMAC key at least as long as the digest.
    secret = "super-secret-shared-key-keep-this-private-please"
    payload = {"sub": "1234567890", "name": "Ada Lovelace", "admin": True}

    print("=" * 70)
    print("STEP 1 — Let PyJWT mint an HS256 token")
    print("=" * 70)
    token = jwt.encode(payload, secret, algorithm="HS256")
    print(f"token: {token}\n")

    header_seg, payload_seg, signature_seg = token.split(".")
    print(f"header    segment: {header_seg}")
    print(f"payload   segment: {payload_seg}")
    print(f"signature segment: {signature_seg}\n")

    raw_hmac = hmac.new(secret.encode("utf-8"), signing_input, hashlib.sha256).digest()
    print(f"raw HMAC-SHA256 (hex): {raw_hmac.hex()}")

    print(f"our base64url signature: {our_signature}\n")

    print("STEP 3 — Compare against the token's signature segment")
    print("=" * 70)
    print(f"PyJWT signature : {signature_seg}")
    print(f"our  signature  : {our_signature}")
    match = hmac.compare_digest(our_signature, signature_seg)
    print(f"\nIDENTICAL? {match}  <-- the 'aha': HS256 signature == base64url(HMAC)\n")

    print("=" * 70)

    decoded = jwt.decode(token, secret, algorithms=["HS256"])

06 Public Key Crypto Intuition06_public_key_crypto_intuition.py ▾

Why is it safe to hand your public key to the entire internet?

Because asymmetric crypto is built on trapdoor functions: math that is easy to compute one way but infeasible to reverse without a secret "trapdoor".

  • RSA rests on integer factorisation. Multiplying two 1024-bit primes is instant; factoring the 2048-bit product back into those primes is infeasible. The public key reveals the product; the private key IS the factors.

  • ECDSA / EdDSA rest on the elliptic-curve discrete log problem. Computing Q = d · G (a point multiplied by a scalar) is easy; recovering the scalar d from Q and G is infeasible. The public key is the point Q; the private key is the scalar d.

So a public key is a "padlock you can mass-produce": anyone can snap it shut (verify), only the trapdoor holder can have produced what fits (sign).

This script keeps it conceptual + tiny demos.

def main() -> None:
    # One key, three representations.
    private_key = rsa.generate_private_key(public_exponent=65537, key_size=2048)
    public_key = private_key.public_key()

    print("=" * 70)
    print("FORMAT 1 — PEM (base64 text with BEGIN/END headers)")
    print("=" * 70)
    pem = public_key.public_bytes(
        encoding=serialization.Encoding.PEM,
        format=serialization.PublicFormat.SubjectPublicKeyInfo,
    )
    print(pem.decode())
    print("Used in: .pem files, env vars, most PyJWT key arguments.\n")

    print("=" * 70)
    print("FORMAT 2 — DER (raw binary ASN.1; shown as a hex preview)")
    print("=" * 70)
    der = public_key.public_bytes(
        encoding=serialization.Encoding.DER,
        format=serialization.PublicFormat.SubjectPublicKeyInfo,
    )
    print(f"DER length: {len(der)} bytes")
    print(f"DER hex preview: {der[:48].hex()}...")
    print("PEM is exactly this DER, base64-encoded, with header/footer lines.\n")

    print("=" * 70)
    print("FORMAT 3 — JWK (JSON, what a JWKS endpoint serves)")
    print("=" * 70)
    # PyJWT can serialise a public key straight to a JWK string.
    jwk_str = RSAAlgorithm.to_jwk(public_key)
    jwk = json.loads(jwk_str)
    pretty = json.dumps(jwk, indent=2)
    # n is long; truncate it for readable teaching output.
    if "n" in jwk:
        jwk_preview = dict(jwk)
        jwk_preview["n"] = jwk_preview["n"][:40] + "...(truncated)"
        pretty = json.dumps(jwk_preview, indent=2)
    print(pretty)
    print(f"\nkty = {jwk.get('kty')}  (key type: RSA)")
    print(f"e   = {jwk.get('e')}  (public exponent 65537 -> 'AQAB' in base64url)")
    print(f"n   = the RSA modulus, base64url-encoded ({len(jwk.get('n', ''))} chars)")
    print("Used in: OIDC /jwks_uri responses, parsed by PyJWKClient/PyJWKSet.")

    print("\n" + "=" * 70)
    print("ROUND-TRIP — JWK back into a usable public key")
    print("=" * 70)
    reconstructed = RSAAlgorithm.from_jwk(jwk_str)
    same = reconstructed.public_numbers() == public_key.public_numbers()
    print(f"from_jwk(to_jwk(key)) yields the same public numbers? {same}")
    print("This is precisely how JWKS-based verification rebuilds keys.")


if __name__ == "__main__":
    main()

"""
08 · The algorithm family grand tour — one alg from each family
================================================================

PyJWT supports five families of signing algorithms. This script signs the SAME
payload with one representative from each, then prints a comparison table of the
header ``alg`` and the resulting signature length.

| Family   | Example | Key type            | Notes                          |
|----------|---------|---------------------|--------------------------------|
| HMAC     | HS256   | shared secret       | symmetric, fast                |
| RSA      | RS256   | RSA private/public  | PKCS#1 v1.5 padding            |
| ECDSA    | ES256   | EC P-256 keypair    | small signatures               |
| RSA-PSS  | PS256   | RSA private/public  | randomised (PSS) padding       |
| EdDSA    | EdDSA   | Ed25519 keypair     | modern, deterministic          |

Note: ECDSA and RSA-PSS are *randomised*, so their signatures differ run to run
even for identical input — that is expected and secure.

Run:
    /home/astro/catalyst/jwt-test/.venv/bin/python \
        pyjwt-course/13-cryptography-deep-dive/08_algorithm_family_tour.py
"""

import base64
import json

import jwt
from cryptography.hazmat.primitives import serialization
from cryptography.hazmat.primitives.asymmetric import ec, ed25519, rsa


def pem_pair(private_key) -> tuple[str, str]:
    """Serialise any asymmetric private key to (private_pem, public_pem)."""
    priv = private_key.private_bytes(
        encoding=serialization.Encoding.PEM,
        format=serialization.PrivateFormat.PKCS8,
        encryption_algorithm=serialization.NoEncryption(),
    ).decode()
    pub = (
        private_key.public_key()
        .public_bytes(
            encoding=serialization.Encoding.PEM,
            format=serialization.PublicFormat.SubjectPublicKeyInfo,
        )
        .decode()
    )
    return priv, pub


def sig_len(token: str) -> int:
    """Decode the base64url signature segment and return its raw byte length."""
    sig_seg = token.split(".")[2]
    padding = "=" * (-len(sig_seg) % 4)
    return len(base64.urlsafe_b64decode(sig_seg + padding))


def main() -> None:
    payload = {"sub": "grand-tour", "iss": "pyjwt-course"}

    # Build a (sign_key, verify_key) for one alg in each family.
    rsa_key = rsa.generate_private_key(public_exponent=65537, key_size=2048)
    rsa_priv, rsa_pub = pem_pair(rsa_key)

    ec_key = ec.generate_private_key(ec.SECP256R1())  # P-256 -> ES256
    ec_priv, ec_pub = pem_pair(ec_key)

    ed_key = ed25519.Ed25519PrivateKey.generate()  # -> EdDSA
    ed_priv, ed_pub = pem_pair(ed_key)

    families = [
        ("HMAC", "HS256", "shared-secret-key-at-least-32-bytes-long!", "shared-secret-key-at-least-32-bytes-long!"),
        ("RSA", "RS256", rsa_priv, rsa_pub),
        ("ECDSA", "ES256", ec_priv, ec_pub),
        ("RSA-PSS", "PS256", rsa_priv, rsa_pub),
        ("EdDSA", "EdDSA", ed_priv, ed_pub),
    ]

    print("=" * 78)
    print("SIGNING THE SAME PAYLOAD WITH ONE ALGORITHM PER FAMILY")
    print("=" * 78)
    print(f"payload: {payload}\n")

    header = f"{'Family':<10}{'alg':<8}{'header.alg':<12}{'sig bytes':<11}{'verify?'}"
    print(header)
    print("-" * 78)

    for family, alg, sign_key, verify_key in families:
        token = jwt.encode(payload, sign_key, algorithm=alg)

        # Read the alg straight out of the (unverified) JOSE header.
        header_seg = token.split(".")[0]
        header_seg += "=" * (-len(header_seg) % 4)
        hdr = json.loads(base64.urlsafe_b64decode(header_seg))
        header_alg = hdr["alg"]

        # Verify it round-trips with the matching key.
        try:
            jwt.decode(token, verify_key, algorithms=[alg])
            verified = "yes"
        except Exception as ex:  # noqa: BLE001
            verified = f"no ({type(ex).__name__})"

        print(f"{family:<10}{alg:<8}{header_alg:<12}{sig_len(token):<11}{verified}")

    print("\n" + "=" * 78)
    print("TAKEAWAYS")
    print("=" * 78)
    print("- The header 'alg' always names the algorithm used to sign.")
    print("- HMAC/RSA/PSS digests vary in size; EC & EdDSA are compact.")
    print("- ES256 & PS256 are randomised: re-running yields a different sig.")
    print("- Choose: HS* (internal), RS*/PS* (RSA infra), ES*/EdDSA (small+fast).")


if __name__ == "__main__":
    main()
